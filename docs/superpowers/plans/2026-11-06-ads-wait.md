# ads_wait Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new ADS tool `ads_wait { symbol, condition, timeoutSeconds? }` (MCP `ads_wait`, Copilot `iecode_ads_wait`) that blocks until a watched PLC value meets a condition, times out, or is cancelled, so an agent stops guessing with sleeps.

**Architecture:** All decisions live in pure modules under `extension/src/core/` (the node tests cannot load `vscode`, so nothing in `src/ads/` is unit-tested): `waitCondition.ts` (grammar and type table), `watchList.ts` (one serialized owner of the watch list with wait holds), `waitRun.ts` (one wait: subscribe, evaluate every row, deadline, cancel, end reasons). `src/ads/host.ts` and `src/ads/adsTools.ts` only wire these to the host process; `mcpTools.ts`, `lmTools.ts` and `package.json` expose the tool.

**Tech Stack:** TypeScript, VS Code extension API, `node --test` (`cd extension && npm test`, which runs `tsc -p .` first). No new dependencies, no CLI change, no protocol bump.

**Spec:** [2026-11-06-ads-mcp-wishlist.md](2026-11-06-ads-mcp-wishlist.md), "Phase 3: `ads_wait` for a condition" and decisions D4, D11, D12, D16-D20 in its decision ledger. This plan is task T0 + Phase 3 of that roadmap; T0's contract is the D16 table, reproduced in Task 1.

## Global Constraints

- Public repository: no internal project names, symbol paths, machine names or data in code, tests, docs or commits. Commits: GitHub noreply author, `git commit -s`, English subject plus a 1-3 sentence why-body.
- The tool is declared once in `extension/package.json` (`languageModelTools`, name `iecode_ads_wait`) and so exists for Copilot and MCP alike; its texts live in `adsToolText.ts` and are pinned by tests.
- Keep the existing tool names and outputs; `ads_watch`, `ads_read`, `ads_scope`, `ads_write` results stay byte-identical (existing tests stay green unchanged, except the tool count in `mcpTools.test.ts`).
- `timeoutSeconds` default 30, clamped to 1-120. The deadline runs from the call start on a monotonic clock (`performance.now()`) and includes host start and the temporary watch add. The MCP cancel signal / Copilot cancellation ends the wait at once.
- Rows count only if stamped at or after the call start (host clock `Date.now()`, same machine). Buffered values and write read-backs never satisfy a wait.
- A null value, a read error, `NaN` or `Inf` never satisfies a condition and never counts as a change.
- Watch list limit stays 200 (`MAX_WATCHED`); a wait on a full list ends at once with the existing limit error text.
- Tests: `cd extension && npm test`. No `dotnet` work in this plan.

## Review Focus

- The user removes, renames or clears the waited symbol in the ADS Watch view during a wait: the wait ends at once with "removed from the watch list by the user", it is not re-added. (Task 3, Task 4)
- The target setting changes or the host restarts during a wait: the wait ends with the host's reason, not after the full timeout. (Task 4, Task 6)
- The waited symbol does not exist on the PLC (item error after the add): the wait ends at once with that error instead of timing out with "no valid value observed". (Task 4)
- Two clients (Copilot and an MCP client, or two MCP connections) wait on the same symbol, one finishes: the other keeps receiving samples. (Task 3)
- The agent waits on a symbol the user already watches: the entry stays the user's and is not removed afterwards. (Task 3)

### Task 1: Condition grammar and type table (`waitCondition.ts`)

**Files:**
- Create: `extension/src/core/waitCondition.ts`
- Test: `extension/test/waitCondition.test.ts`

**Interfaces:**
- Consumes: `Parsed<T>` from `extension/src/core/toolInput.ts`; `WatchItem` from `extension/src/core/adswatch.ts`.
- Produces:
  ```ts
  export type Literal =
    | { kind: 'int'; value: bigint } | { kind: 'real'; value: number } | { kind: 'bool'; value: boolean }
    | { kind: 'name'; value: string } | { kind: 'string'; value: string };
  export type CompareOp = '=' | '<>' | '<' | '<=' | '>' | '>=';
  export type WaitCondition = { op: CompareOp; literal: Literal } | { op: 'changes' } | { op: 'contains'; text: string };
  export type ValueClass = 'integer' | 'real' | 'bool' | 'enum' | 'string' | 'other';
  export function parseCondition(text: string): Parsed<WaitCondition>;
  export function classify(item: WatchItem, text: string | null, enumValue: number | null | undefined): ValueClass;
  export function applicable(cond: WaitCondition, cls: ValueClass): string | undefined; // error text, undefined = allowed
  export function isValid(cls: ValueClass, text: string | null): boolean;
  export function meets(cond: WaitCondition, cls: ValueClass, text: string, enumValue: number | null | undefined, baseline: string | undefined): boolean;
  export const conditionText: (cond: WaitCondition) => string; // canonical form for result texts, e.g. `= 40`, `contains "Err"`
  ```

The type table (D16) this task implements:

| class | allowed literal | `=` `<>` | `<` `<=` `>` `>=` |
|---|---|---|---|
| integer | `int` | `BigInt(text)` exact | yes, `BigInt` |
| real | `int` or `real` | `Number(text) === value` (so `1.5` = `1.50`), no epsilon | yes |
| bool | `bool` | yes | no |
| enum | `name` (case-insensitive vs. text) or `int` (vs. `enumValue`) | yes | `int` only |
| string | `string` | exact, case-sensitive | no |
| other | `string` | exact text | no |

`classify`: `enumValue` not null → `enum`; type name (upper-cased, `STRING(80)` → `STRING`) in SINT INT DINT LINT USINT UINT UDINT ULINT BYTE WORD DWORD LWORD → `integer`; REAL LREAL → `real`; BOOL → `bool`; STRING WSTRING → `string`. For an unknown type name (an alias) fall back on the value: `TRUE`/`FALSE` → `bool`; `item.numeric` and `/^-?\d+$/` → `integer`; `item.numeric` and a finite number → `real`; else `other`. `changes` is allowed for every class; `contains` for `string` and `other` (case-sensitive).

`parseCondition` grammar (whitespace around tokens allowed): `changes`; `contains "<text>"`; `<op> <literal>` where literal is `"…"` (backslash escapes `\"` and `\\`) → `string`, `TRUE`/`FALSE` (any case) → `bool`, `-?\d+` → `int`, a finite decimal (`-?\d+\.\d+`, optional exponent) → `real`, an identifier `[A-Za-z_][A-Za-z0-9_]*` → `name`. Anything else → `{ ok: false, error: 'condition must be one of: = v, <> v, < v, <= v, > v, >= v, changes, contains "text"' }`. Condition text longer than 512 characters → `condition is longer than 512 characters`.

### Task 3: One serialized owner of the watch list with wait holds (D11, D17)

**Files:**
- Create: `extension/src/core/watchList.ts`
- Test: `extension/test/watchList.test.ts`

**Interfaces:**
- Consumes: `WatchEntry`, `watchEdit`, `watchRename` from `extension/src/core/adswatch.ts`.
- Produces:
  ```ts
  export interface WatchListDeps { entries(): WatchEntry[]; set(entries: WatchEntry[]): Promise<unknown> }
  export class WatchList {
    constructor(deps: WatchListDeps);
    /** AI add/remove (ads_watch). Returns the removals refused because the user owns them. */
    aiEdit(add: string[], remove: string[]): Promise<{ kept: string[] }>;
    /** Any user edit: `edit` maps the current entries to the next ones (watchEdit, watchRename, filter, []). */
    userEdit(edit: (current: WatchEntry[]) => WatchEntry[]): Promise<void>;
    /** Keeps the symbol watched for a wait; adds it as an AI entry when missing. */
    hold(symbol: string): Promise<WaitHold>;
    /** Fires with the symbols (as held) a user edit removed while a wait held them. */
    onUserRemoved(listener: (symbols: string[]) => void): { dispose(): void };
  }
  export interface WaitHold { readonly symbol: string; release(): Promise<void> }
  ```

Rules: every method enqueues one step on a single promise chain and reads `deps.entries()` when the step runs, never before an `await`. A failed `set` rejects that call and leaves the chain usable. Holds are a case-insensitive reference count per symbol plus a flag "added by a hold". `release` of the last hold removes the entry only if a hold added it, no `aiEdit` add touched it meanwhile, and the user did not take it over (`watchEdit` with `byAi = false` clears the AI flag; check the flag at release). `aiEdit` remove of a held entry removes nothing now and clears "added by a hold" protection only for the add, so the entry goes away when the last hold releases. A user edit that drops a held symbol fires `onUserRemoved` and drops the hold count for it (its later `release` is a no-op). `release` is idempotent. `hold` on a full list (200) rejects with the existing `watchLimitError` text.

### Task 4: One wait run (`waitRun.ts`, D4, D19, D20)

**Files:**
- Create: `extension/src/core/waitRun.ts`
- Test: `extension/test/waitRun.test.ts`

**Interfaces:**
- Consumes: Task 1 (`WaitCondition`, `classify`, `applicable`, `isValid`, `meets`), Task 3 (`WaitHold`), `Row`, `WatchItem` (Task 2 export).
- Produces:
  ```ts
  export interface SampleBatch { gen: number; items: WatchItem[]; rows: Row[] }
  export interface WaitDeps {
    hold(symbol: string): Promise<{ release(): Promise<void> }>;
    ready(): Promise<void>;                       // host started (awaited, not fire-and-forget)
    onSamples(l: (b: SampleBatch) => void): { dispose(): void };
    onEnded(l: (reason: string) => void): { dispose(): void };       // host stop, restart, target change
    onUserRemoved(l: (symbols: string[]) => void): { dispose(): void };
    monotonicMs(): number;                        // performance.now()
    wallMs(): number;                             // Date.now(), the host's row clock
    setTimer(ms: number, fn: () => void): { dispose(): void };
  }
  export type WaitOutcome =
    | { kind: 'met'; t: number; value: string; firstObservation: boolean; elapsedMs: number }
    | { kind: 'timeout'; last: string | undefined; seconds: number }
    | { kind: 'ended'; reason: string }
    | { kind: 'refused'; reason: string }
    | { kind: 'cancelled' };
  export function runWait(deps: WaitDeps, req: { symbol: string; condition: WaitCondition; timeoutSeconds: number }, signal: AbortSignal): Promise<WaitOutcome>;
  ```

Behaviour: start time `t0 = wallMs()` and deadline `monotonicMs() + timeoutSeconds * 1000` are taken first. Subscribe to `onSamples`, `onEnded`, `onUserRemoved` *before* `hold`, so no batch between add and subscribe is lost. Then `hold`, then `ready`. One idempotent `finish(outcome)` resolves once, disposes subscriptions and the timer, and releases the hold; if `hold` is still pending when the call finishes, its release runs when it resolves. For each batch: find the column whose `items[i].symbol` equals the symbol case-insensitively (none → skip the batch); an item `error` → finish `refused` with that error; each row with `t >= t0` in order: classify; on the first classified row check `applicable` (error → `refused`); skip invalid values (`isValid` false); the first valid row is the `changes` baseline (`changes` never meets on it) and sets `firstObservation`; `meets` → `met` with that row's `t` and text. Track the last valid text for the timeout. Timer at the deadline → `timeout`; `signal` abort (also already aborted) → `cancelled`; `onEnded` → `ended` with the reason; `onUserRemoved` containing the symbol → `ended` with `removed from the watch list by the user`; a rejected `hold` or `ready` → `refused` with its message.
