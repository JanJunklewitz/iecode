What you see

  • TwinCAT Projects view new – tree built by parsing .sln → .tsproj → .plcproj; mirrors XAE's folder structure (FolderPath), shows methods/properties/actions as children. Click jumps to the section.
  • Plain-ST editor PoC exists – one document per POU, sections for members; save splices only changed CDATA; XML stays the source of truth. ST ⇄ XML toggle in breadcrumbs.
  • Build / Activate / Library buttons in the status bar & command palette → call iecode with --json; errors land in Problems, mapped back to view lines new.
  • Context menu on folders/POUs: Add ▸ FB / Function / Program / Method / Property / Action / Interface / DUT / GVL … (see tab 2).
  • Later: outline, go-to-definition, find references, rename across files (needs an ST language model — see scope).

One VS Code workspace holds several libraries and PLC applications side by side: either one folder with many solutions (monorepo), or a multi-root .code-workspace that pulls in several repos. The extension finds every .sln, .tsproj and standalone .plcproj, works out which projects are libraries, and links library references to library projects in the same workspace.

Workspace features

FeatureWhat it does
DiscoveryScans all workspace folders for .sln / .tsproj / .plcproj. Libraries are detected from the project's library metadata (company, title, version) or marked in the workspace config. Grouped into Libraries / Applications / Standalone PLC.
Workspace links keyA reference to Tc3_MotorLib in an application can point to the library project in the workspace (⇄ workspace) instead of an installed version. On build, iecode saves and installs the library as a -dev version first, then builds the app against it. Like npm link / project references in .NET.
Cross-project navigationGo to definition from MachineX into Tc3_MotorLib's source; "Find usages" of I_Motor.Start across all apps in the workspace.
Dependency graphWhich project uses which library and version; build order; which projects are affected by an uncommitted change.
Build affected / Build allBuilds changed libraries and their dependents in order. Same command in CI: iecode ws build --affected --since origin/main.
Release a libraryTwinCAT: Release library… → bump version (patch / minor / major), save as .library, publish to a feed, and offer to update all dependents in the workspace (pinned ones are listed but not touched).
Active projectStatus bar picks which application Build / Activate / target apply to; each application keeps its own target NetId.
One TwinCAT shelliecode keeps one XAE shell alive for a whole workspace build instead of starting one per solution (saves ~5–10 s per project).

Reproducible builds: the .plcproj is the single source of truth decided

</PlaceholderReference>
<PlaceholderResolution Include="Tc3_MotorLib">
  <Resolution>Tc3_MotorLib, 1.3.0 (MachineX GmbH)</Resolution>
</PlaceholderResolution>
How it works
  • No extra manifest file. Pinning a version in the manager writes a fixed resolution into the .plcproj.
  • iecode lib restore reads the pinned versions from the .plcproj files and installs missing ones from the configured sources before building (CI / fresh machine).
  • References set to * (newest) are reported as a warning in CI, because they aren't reproducible.
  • Library changes show up as a diff of the .plcproj in pull requests.

iecode – single self-contained Windows exe (C#/.NET 8, COM interop to EnvDTE + TCatSysManagerLib). Human-readable output by default, --json for the extension and CI. Non-zero exit code on any error.

PS> iecode --help iecode 0.1.0 – TwinCAT Automation Interface from the command line USAGE iecode <command> [solution.sln] [options] PROJECT build Build solution or a single PLC project; errors as file:line check "Check all objects" without full build activate Activate configuration on target (optionally restart TwinCAT) info List PLC projects, references, target, TwinCAT version doctor Check TwinCAT / XAE shell / ADS route / iecode version self-update Update iecode (GitHub install only; tcpkg installs use tcpkg) LIBRARIES lib save Save PLC project as .library or .compiled-library lib search Search configured sources (feeds, folders, tcpkg) lib add / remove Add or remove a library reference in a PLC project lib install Install a .library into the local repository lib update Update library references in one or many projects lib outdated List references with newer versions available lib restore Install the versions pinned in the .plcproj files lib publish Push a .library to a company feed lib list Show references + resolved versions WORKSPACE (reads twincat-workspace.json or scans the folder) ws list Libraries, applications, standalone PLC projects ws graph Dependency graph + build order (text, JSON, Mermaid) ws build Build all, or --affected [--since <git-ref>], in order ws release <lib> Bump version, save, publish, update dependents PROTECTION encrypt Compiled library, or encrypt a project with a user DB GLOBAL OPTIONS --tc <version> TwinCAT to use: 4024 | 4026 | exact build, e.g. 4024.66 | auto (default: auto = version stored in the .tsproj, else newest installed) --visible Show the XAE shell window (debugging) --json Machine-readable output --timeout <s> Abort after s seconds (default 900)

VS Code extension (TypeScript) any OS

  • xml/model – parse/splice TcPOU/TcIO/TcDUT/TcGVL (from PoC)
  • project – read .sln/.tsproj/.plcproj, build tree, add/remove Compile Include
  • generators – templates for every object type (fresh GUIDs, CRLF, BOM like XAE)
  • views – tree, iecode: file system, outline, status bar
  • iecode bridge – spawn iecode --json locally on Windows; map diagnostics. On macOS / Linux the iecode commands are hidden and the extension is an editor only.

iecode CLI (C# / .NET 8) Windows + TwinCAT XAE

  • Shell host – create TcXaeShell.DTE.17.0 / VisualStudio.DTE.17.0, COM IMessageFilter for retry, always quit the shell
  • Build – SolutionBuild.Build, read ErrorList
  • Activate – ITcSysManager.SetTargetNetId / ActivateConfiguration / StartRestartTwinCAT
  • Library – ITcPlcIECProject.SaveAsLibrary, ITcPlcLibraryManager (Install, Add/Remove reference, SetEffectiveResolution)
  • Encrypt – SaveAsLibrary as .compiled-library; project encryption + user DB link via TwinCAT 3 Security Management (AI coverage to verify)

Vendor adapters (prepared for CODESYS and Siemens later)

Everything vendor-specific sits behind one interface. The tree, workspace, library manager, language features and CLI commands only talk to the interface. TwinCAT is the first and, for now, only adapter.

The extension keeps a workspace model (all projects, library metadata, references, links) shared by the tree, the library manager and navigation. iecode ws … builds the same model from twincat-workspace.json so CI and the editor agree on build order.
